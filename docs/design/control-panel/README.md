## 1. 画面の構成(ルート)

| 画面 | URL | キャンバス | 中身 |
|---|---|---|---|
| 配信中 | `/control-panel` | Main / LiveNarrow | 配信中に押すものだけ(下の 3 章) |
| 準備 | `/control-panel/prepare` | Prepare | 配信の前に決めるもの(4 章) |
| 振り返り | `/control-panel/review` | (なし) | 今のカードを移すだけ(5 章) |

- `/control-panel` は **配信中** を開く(配信中にページを開き直しても 1 手で戻れるように)。
- 共通部分は `app/control-panel/layout.tsx` に置く: `ThemeProvider`(`theme.ts`)、ヘッダー、テロップの数字キー、休憩の状態。
- フェーズの切り替えは普通のリンク(`next/link`)。選んだフェーズを覚えておく必要はない。

## 2. 共通ヘッダー(全画面)

左から: アイコン(`icon.svg`、28px)+「配信パネル」/ フェーズの切り替え(準備・配信中・振り返り。丸いセグメント、今のフェーズはピンクの塗り)/ 余白 /「変更はすぐ保存」(緑のチェック+小さい文字)/ 休憩ボタン / 設定(歯車のアイコンボタン、`aria-label="設定"`)。

- **休憩ボタン**: 今の `BreakControl` をヘッダーに移す。
  - 休憩していないとき: 枠線のボタン「休憩する」(warning 系の色。`theme.ts` の `warningSoft` 背景)。
  - 休憩中: 塗りのボタン「休憩を終わる 12:34」に変わり、ヘッダーの下に全幅の帯「休憩中 12:34 ―「ただいま」と話すか、右上のボタンで終わります」を出す。
  - 長い休憩・休憩中に声を拾ったときの点滅とタブのタイトル表示は、**今の動き(`BREAK_LONG_MS` = 10 分、`voiceHeard`)をそのまま**残す。点滅は帯とボタンの両方に。
  - 帯の「10 分」は `BREAK_LONG_MS` から出す(決め打ちしない)。
- **数字キーのテロップ**: `TelopBar` の keydown の処理を `useTelopHotkeys()` などのフックに出して layout で 1 回だけ登録する。**どのフェーズの画面でも**今までどおり 1〜9・0 で先頭 10 個が出る(入力欄にフォーカスがあるときは効かない、`isEditableTarget` もそのまま)。
- 幅 600px 未満: フェーズの切り替えを `<select>` に、休憩を短い表記に、「変更はすぐ保存」は隠す(キャンバス LiveNarrow 参照)。

## 3. 配信中の画面

### レイアウト

- カードを 3 列に並べる。列は `display: flex; flex-wrap: wrap; gap: 16px` で、各列 `flex: 1 1 380px`(3 列目だけ 340px)、`min-width: 0`。最大幅 1600px で中央寄せ。
- **DOM の順番 = 狭いときに縦に並ぶ順番 = 優先度**:
  1. 列 1: テロップ → エフェクト・クリップ
  2. 列 2: サーモンラン → ときどき直すもの
  3. 列 3: 視聴者参加 → 本日のお題
- 幅 600px 未満(`useMediaQuery` か CSS の container query)は **コンパクト表示**(キャンバス LiveNarrow):
  - 上から: テロップ(先頭 10 個、2 列)→ サーモンラン(取り込み+手入力、成績は 1 行)→ 視聴者参加(受付中のときだけ。状態・いまの人・次の人だけ)→ 本日のお題
  - 残り(ほかのテロップ・エフェクト・クリップ・記録の一覧・ときどき直すもの・列の一覧・キケン度・お知らせ)は最後の折りたたみ 1 つにまとめる
- ボタンの高さ: 配信中の主ボタンは 52〜64px、テロップのキーは 52px(コンパクト 46px)、そのほかも 44px 以上。

### カードの中身と、今のコードとの対応

**テロップ**(今の `TelopBar` を置き換え)
- 先頭 10 個: 2 列のグリッド。左にキーの番号のバッジ(ピンクの角丸、等幅の数字)、右に文。長い文は 1 行で省略(`text-overflow: ellipsis`)。
- 押した(または数字キーで出した)プリセットは、`/api/telop` の成功後、テロップが出ている間(約 4 秒)ピンクの枠と「表示中」を出す。
- 11 個目以降: 「ほかのテロップ(20)」のボタンで開閉する小さいボタンの並び。開閉の状態は localStorage に覚える。チャットだけのプリセット(`display: false`)にはチャットのアイコンを付ける。
- 見出しの右に「キーボードの 1〜0 でも出せます」。

**エフェクト・クリップ**
- 5 つのボタンを横に並べる: LOVE / STAR / SPARKLE / BUBBLE / クリップ(アイコン+小さいラベル、高さ 64px)。見出しの右に「声でも出せます」。
- **エフェクトは `PATCH /api/stream-data`(`{event: 'STAR'}`)で送る**。今の `handleTriggerEffect` は POST で未反映の編集もいっしょに送ってしまうので、それを直す。
- クリップは `ClipPanel` の「今クリップする」と同じ処理。履歴は、カードの見出しの右に小さい「履歴」ボタンを置き、開くダイアログに今の履歴の表示をそのまま入れる。

**サーモンラン**(今の `SalmonRunPanel` を分ける)
- 見出しの右にセッションのチップ(`#25 どんぴこ闘技場` のように番号とタイトル)。
- **「リザルトを取り込む」**: 緑の塗りの大きいボタン(高さ 64px、横いっぱい)。その右に「手入力」(72×64、枠線)。下に「最後の取り込み 20:47(30 バイト目)」。
- **手入力**は今の記録フォームを **ダイアログ** に移す。支給ブキのパレットは最初は閉じておき、「ブキを選ぶ」を押したときだけ開く(ダイアログの中で開く。今のパレットの部品をそのまま使ってよい)。ステージとバイトの種類は前回の値を入れておく(今と同じ)。
- 本日の戦績: 4 つのタイル(金イクラ・オオモノ・デス・クリア)。大きい数字が本日の合計、下に前回の値。数字は `font-variant-numeric: tabular-nums`。
- 「このセッションの記録」: 新しい順に 3 件(番号・クリア/失敗・金・オオモノ・デス・時刻・✏️ で直す)。「すべての記録(30)と修正・削除」で今の一覧(修正・削除つき)をダイアログかドロワーで開く。
- 移すもの: 「新しいセッションを開始」→ 準備、「過去のセッション」「振り返りの画像」→ 振り返り。

**ときどき直すもの**(小さいカード、行 2 つ)
- スコア表示: 「スコア表示 でんせつ 999 自動」+「直す」ボタン(今の `ScoreDisplayPanel` の値の入力をダイアログで)。自動更新の ON/OFF は設定へ。
- ブキ埋めカード: 「ブキ埋めカード 42 / 70」+「埋める・外す」(今の `WeaponCardPanel` の手動の部分をダイアログで)。画像のダウンロード・新しいカードは振り返りへ。

**視聴者参加**(今の `JoinQueuePanel` を分ける)
- 受付していないとき: 灰色のチップ「受付していません」+ ピンクの大きいボタン「受付を始める」+ 一言の説明だけ。カードは小さく。
- 受付中: カードの枠を緑にして、チップ「受付中 · 列 3 人」。中身は上から いまの人(名前と評価)→ **「次の人を呼ぶ」**(ピンクの塗り、高さ 52px)→ 列(番号・名前・評価・× で外す)→ 部屋の推定キケン度(1 行の要約)→ 「合流のお知らせ」「プラベのお知らせ」(枠線の小さいボタン)と「受付を終わる」(赤い文字だけのボタン)。
- 評価をこの画面だけに出す決まり・接続し直したときの警告は今のまま残す。
- 移すもの: 配信者の評価の入力 → 準備、これまでの受付(28 日)→ 振り返り。キケン度の詳しい内訳(練習・通常・腕試し)は要約をクリックで開く。

**本日のお題**
- 達成のチェックだけ(行の高さ 48px、チェックボックス 22px、`<label>` で行全体を押せるように)。達成したものは文字を薄く。見出しの右に「1 / 3 達成」。
- お題の追加・削除は準備へ(今は `SidePanelSettingsPanel` の中にある)。

## 4. 準備の画面

2 列(各 `flex: 1 1 420px`、最大幅 1200px)。

- **今日の配信**(左上、ピンクの淡い面で目立たせる): セッションのタイトル(任意)+ **「配信を始める」**。押すと今の「新しいセッションを開始」と同じ処理をしてから `/control-panel`(配信中)へ移る。下に「いまのセッション: #25 11/16 17:00 どんぴこ(30 バイト)」。
- **本日のお題**: 一覧(並べ替えのつまみ・× で削除)+ 入力欄と「追加」。「3 / 8」。改行・文字数の決まりは今の `normalizeChallengeText` のまま。
- **サイドパネル**: 固定枠(セレクト)、フォロワー目標、ローテーション枠(切り替えチップ。ON は緑)、切り替えの秒数。中身の決まり(同じものを両方に入れない、バーンダウンは単独)は今のまま。
- **参加型の準備**: 配信者の評価(取り込んだ記録の値を表示+「手で入れる」)。
- **流すメッセージ・バーンダウン**: メッセージのプリセットの選択(チップ)とメッセージの追加・削除、バーンダウンの名前・目標値・ポイントの追加。

## 6. 設定の画面

左にメニュー(幅 200〜240px。600px 未満は上にセレクト)、右に中身。メニュー:

| メニュー | 中身 | 今の場所 |
|---|---|---|
| テロップのプリセット | 自由入力 + プリセットの編集(下記) | テロップタブ |
| 読み上げ(VOICEVOX) | `VoiceSettingsPanel` そのまま | テロップタブの下 |
| スコア表示の自動更新 | ON/OFF | スコア表示タブ |
| 見た目 | フォント・フォントサイズ・メッセージの切り替えエフェクトと表示秒数 | 共通設定・メッセージタブ |
| OBS のブラウザソース | オーバーレイの URL と大きさの一覧 | 全タブの下 |
| その他 | 入力キャッシュのクリア(7 章の移行が済んだら消してよい) | 共通設定タブ |

**テロップのプリセットの編集**(今の「1 文字ずつ折り返して縦に長くなる」を直す)
- 1 行 = 1 プリセット: 並べ替えのつまみ / 番号のバッジ(先頭 10 個はピンク=数字キー、それ以降は灰色)/ **文の入力欄(1 行、`flex: 1 1 240px`)** / 4 つのアイコンのトグル(テロップに出す・チャットにコメント・読み上げ・共通フォント。`aria-pressed`、40×40)/ 削除。
- 幅が足りないときはトグルの並びが入力欄の下に折り返す(`flex-wrap`)。
- アイコンの凡例を一覧の上に 1 行で出す。「テロップに出す」と「チャット」が両方 OFF にならないよう、最後の 1 つは押せなくする(今のバリデーションと同じ)。
- 上に「自由入力で出す」(入力欄+「出す」)。

**OBS のブラウザソース**
- `app/page.tsx` の `OVERLAY_PAGES` を `lib/overlayPages.ts` に移し、ランチャーと設定の両方から使う(今の 3 つだけの古い一覧は消す)。
- 1 行 = 1 オーバーレイ: 名前 / `origin + href`(等幅、コピーのボタン)/ 幅×高さ(無いものは「音声のみ」)。

## 7. 保存のしかたをそろえる

今は、ほとんどがその場で保存だが、**バーンダウン・メッセージ・フォント・切り替えエフェクト** だけが `localStorage` の `formData` にたまり、「OBSに反映」で `POST /api/stream-data` を送るまで反映されない。しかもサーバー側の `streamData` はメモリだけなので、再起動で消える。

直し方:
1. `streamData` のうち上の項目を、ほかの設定と同じように SQLite(`app_state`)に保存する(スコア表示は今も SQLite)。
2. 画面では入力が変わったら 500ms ほど待って(debounce)保存の API を送る。送るのは変わった項目だけにできるとよい(`PATCH` を項目ごとに分けるか、POST を部分更新にする)。`lastEvent` は送らない。
3. 「OBSに反映」の固定ボタンと成功・失敗の表示を消す。保存に失敗したときだけ、ヘッダーの「変更はすぐ保存」を赤い「保存できませんでした」に変える(どの画面にいても見えるように)。
4. 移行: 初めて開いたとき、SQLite に保存が無く `localStorage` に今の `formData` があれば、それを 1 回だけ保存して `localStorage` の値を消す。
5. エフェクトは 3 章のとおり `PATCH {event}` に変える。

## 8. 見た目(`theme.ts`)

- `theme.ts` を `app/control-panel/theme.ts`(など)に置き、今の `page.tsx` の `darkTheme` と置き換える。背景のぼかした丸(ピンクと緑)は消す。
- 色・角丸・文字・余白・ボタンの高さは `theme.ts` の `tokens` とキャンバスの「デザインの決まり」を見る。要点:
  - 面: background `#0E1014` / ヘッダー `#12151B` / カード `#161A21` / 1 段上の面 `#1E232C` / 枠 `#262B35`・`#343B48`
  - 文字: `#ECEEF2`、薄い文字 `#9AA3B2`(小さい文字でもコントラスト 4.5:1 を満たす。これより薄い色を文字に使わない)
  - **アクセントの上の文字は白ではなく濃い色**(ピンクの上は `#1A0710`、緑の上は `#062312`)。白だとピンクの上で 3:1 を切る
  - 角丸: バッジ 6 / 小ボタン 8 / ボタン・入力 10 / 主ボタン 12 / カード 14 / チップ 999
  - 余白は 4 の倍数。カードの中 16、カードの間 16、画面の端 20(狭いとき 12)
  - 文字: Inter + Noto Sans JP、キーの番号だけ JetBrains Mono(どちらも `next/font/google` で読み込む)
  - カードは面の色+1px の枠だけ。影・グラデーション・すりガラス(`backdropFilter`)は使わない
- アイコン: 見出しの絵文字(🐟 📜 📸 🦑 📝 …)をやめ、MUI の Rounded / Outlined 系のアイコンにする。プリセットの文の中の絵文字はそのまま。
- アクセシビリティ: アイコンだけのボタンには `aria-label`、トグルは `aria-pressed`、受付中・休憩中の変化は `role="status"` で伝える。

## 10. 進め方(PR の分け方の案)

上から順に。各 PR でテスト(`page.test.tsx` などの既存のテスト)を直して通す。

1. **テーマとアイコン** — `theme.ts` を入れて `darkTheme` を置き換え、アイコンを差し替える。画面の構成は変えない。
2. **保存の統一** — 7 章。「OBSに反映」を消す。エフェクトを `PATCH` に。
3. **ルートと共通レイアウト** — `layout.tsx`、ヘッダー、フェーズの切り替え、数字キーのフック、休憩をヘッダーへ。中身はとりあえず今のタブを各画面に振り分けるだけでよい。
4. **配信中の画面** — 3 章。`SalmonRunPanel`・`JoinQueuePanel`・`TelopBar` の分割、手入力のダイアログ。
5. **準備の画面** — 4 章。「配信を始める」。
6. **振り返りの画面** — 5 章(移すだけ)。
7. **設定の画面** — 6 章。テロップのプリセットの編集、OBS の URL 一覧。
8. **狭い幅の仕上げ** — 3 章のコンパクト表示。幅 400px と 1440px で確認。

## 12. 決めきれていないこと(実装しながら決めてよい)

- クリップの履歴の置き場所(この文書ではエフェクト・クリップのカードの「履歴」ダイアログにした。振り返りに置いてもよい)
- 入力キャッシュのクリアを消すかどうか(7 章の移行が済めば要らないはず)
- キャンバスの視聴者名(視聴者A〜D)、お題の 2・3 個目、メッセージのプリセット名(実際は 通常・大会・ビッグラン・バチコン・その他)、ブキ埋めの 42 / 70、キケン度の数字は見本の値
