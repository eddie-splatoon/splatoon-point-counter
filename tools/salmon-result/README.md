# salmon-result

サーモンランの最新のリザルトを、iPhone ミラーリングに映した NSO アプリ（イカリング3）から読み取って記録するスクリプトです。
コントロールパネルの「サーモンラン」タブの「📸 イカリング3から最新のリザルトを取り込む」を押すと動きます。

- イカリング3の API は直接呼びません。公式アプリの画面をタップ・スクロールして、映っている文字を読むだけです
- 文字の読み取りは macOS の Vision、支給ブキはアイコンを参照画像（Leanny/splat3）と照合します
- 画面を操作するので、Docker ではなく **Mac 上でネイティブに実行** してください（macOS 15 以降の iPhone ミラーリングが必要）

## 流れ

1. ボタンを押すと `/api/salmon/import` に依頼が入り、このスクリプトが 1 秒以内に拾います
2. バイトの詳細画面の「最新のバイトへ」を押して、最新のバイトを表示します（ヒストリーはタブを移っても読み込み直されないため）。詳細画面でなければ、ヒストリーのいちばん上のバイトを開いてから押します
3. 詳細画面を撮影して `data/salmon-results/` に保存し、自分の金イクラ・オオモノ・デス（被救助数）・クリア / 失敗した WAVE・ステージ・日時・支給ブキを読み取ります。あわせて詳細（キケン度・評価・獲得ポイント・チームのイクラ・ウロコ・WAVE ごとの納品数 / ノルマ・潮位・イベント・金イクラ出現数・使われたスペシャルの数・オカシラ、4 人の成績・ブキ・スペシャル）も読みます
   続けて詳細画面を少しずつ下にスクロールして「倒したオオモノシャケ」の欄を撮影し（`*-bosses.png`）、オオモノごとの出現数・チームの討伐数・自分の討伐数を読んでから、先頭に戻します
4. 取りこぼしがあれば、「前のバイト」で記録済みのバイトまで遡って読み取ります（今のセッションの開始より前のバイトと、21 件目以降は遡りません）
5. 結果を古い順に送ると、サーバーが今のセッションに記録します。テロップで「リザルトを記録しました」と出ます
6. 最新のバイトが記録済みなら、イカリング3にまだ反映されていないので、15 秒ごとに読み直します（最大 4 分）

クリック・スクロールのたびに、マウスカーソルの位置と前面のアプリを元に戻します（一瞬だけミラーリングが前面になります）。
読み取れない項目があれば、推測で記録せずに失敗にします（支給ブキだけは、照合できなければ記録しません）。
詳細は「おまけ」なので、読めない項目は空（null）にして記録を続けます。詳細の読み取りで想定外のエラーが起きても、金イクラなどは記録します。
オオモノごとの数は、自分の討伐数の合計が自分の行の「オオモノシャケ xN」と合わなければ（読み間違い・取りこぼし）記録しません。
味方の名前は DB に残しますが、ログ・`--read` の出力・API・配信画面には出しません。読み間違えたときは、コントロールパネルの戦績から削除してください。削除したバイトは取り込み直せます。

## 準備

1. Next.js アプリを起動する（`pnpm dev` または `docker-compose up`）
2. iPhone ミラーリングを開き、NSO アプリでイカリング3の「サーモンラン」タブを表示しておく（ミラーリングのウインドウは最小化しない。ほかのウインドウに隠れていても動きます）
3. ターミナル（このスクリプトを起動するアプリ。Terminal・iTerm・エディタの内蔵ターミナルなど、実際に起動するアプリ）に、システム設定 → プライバシーとセキュリティで次の権限を与える
   - **デバイスの制御とデータへのアクセス**（macOS 26 までは「アクセシビリティ」。クリック・スクロールのため。権限が無いとクリックが黙って無視され、画面が移らずに失敗します。起動時に警告が出ます）
   - **画面収録**（ミラーリングを撮影するため）

   権限を与えたら、そのアプリを再起動してください
4. リポジトリのルートで起動する（`Ctrl+C` で終了）

   ```bash
   pnpm salmon-result
   ```

初回は venv の作成と依存のインストール、ブキ・スペシャルの参照画像のダウンロード（`data/salmon-weapon-refs/`）を行います。

ミラーリングの接続が一時停止していたら、「再開」を押してつなぎ直します。

## 読み取りの確認・調整

保存したキャプチャを読み取って、結果を表示できます（記録はしません）。

```bash
pnpm salmon-result --read data/salmon-results/20261110-210503-detail.png
```

オオモノの欄のキャプチャ（`*-bosses.png`）を渡すと、見えているオオモノの行を表示します。

イカリング3の見た目が変わって読めなくなったら、`salmon_result.py` の次の箇所を直します。

- `SelfRowCells`: 自分の行の金イクラ・被救助数の位置と、支給ブキのアイコンを探す範囲（「オオモノシャケ」の文字を基準にした相対位置）
- `PlayerRowCells`: 各プレイヤーの行の赤イクラ・救助数・名前の位置（同じく相対位置）
- `WAVE_*_ROW`: WAVE の列の各段（納品数・潮位・イベント・金イクラ出現数・スペシャル）の位置（「WAVE n」の見出しを基準にした相対位置）
- `read_header`: 上部（キケン度・評価・ポイント・ウロコ）の位置
- `BOSS_*`: オオモノの欄の位置（名前の左端・数の列）とスクロールの量。数字は OCR では読み間違えるので、`digit_glyphs.py` の数字・カッコの形と照合しています。形が変わって読めなくなったら、新しいキャプチャから切り出し直してください
- `KNOWN_GRADES` / `KNOWN_KINGS` / `WATER_LEVELS`: 読み間違い（さんせつ・普渔 など）を直すための既知の値
- `open_latest_job` / `open_previous_job`: 画面の移動の手順（`NEXT_JOB_BUTTON_REGION` は「次のバイト」のボタンの位置）
- `KNOWN_STAGES`: ステージ名の読み間違いを直すための既知のステージ

## 環境変数

| 変数 | 既定値 | 内容 |
|---|---|---|
| `SALMON_API_BASE` | `http://localhost:3000/` | Next.js アプリの URL |
| `SALMON_CAPTURE_DIR` | `data/salmon-results` | キャプチャの保存先 |
| `SALMON_WEAPON_REFS_DIR` | `data/salmon-weapon-refs` | ブキの参照画像のキャッシュ（スペシャルは `specials/`） |

## テスト

`fixtures/` に実際の詳細画面（クリア・失敗・オカシラあり）と、オオモノの欄までスクロールした画面（`bosses-*.png`）を置いています。画面を追加するときは、プレイヤー名を塗りつぶしてください。

```bash
cd tools/salmon-result
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```
